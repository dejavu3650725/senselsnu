# ★ SEN SEL (센셀) — 교실 속 보이지 않는 마음을 읽는 AI 사회정서 레이더

학생은 나무 캐릭터 챗봇과 편하게 이야기하고, 교사는 그 대화에서 나온 관계 신호로 학급 관계망·자리 배치·맞춤 지도·가정 연계·학교 서류까지 한 곳에서 처리하는 웹 서비스입니다. 서울특별시교육청 교사 개발자 해커톤 성장형 연수에서 시작해, 실제 학급 적용과 검토를 거듭하며 고도화했습니다.

- 배포: https://senselsnu.vercel.app
- 체험 학급 **SENSEL**(프로그램 내장, 로그인 후 학급 목록에서 바로 입장) — 관계망·신호·대화 샘플에 더해 성장 기록·주간 미션·반복 호소 사례·조치 메모가 남은 알림·보호자 동의 현황(동의/미동의/미회신)·자유 대화 모드 학생·최근 발행 학급 리포트·가정 회신·전자 동의 제출까지 채워져 모든 화면을 시연할 수 있습니다
- 판단 근거: 교육부 한국형 사회정서교육 → 서울시교육청 사회정서교육자료(초1~고3) → 2022 개정 도덕과 교육과정 → 서울시교육청 AI·에듀테크 가이드라인 → 서울시교육청 공식 서식. 개발자의 임의 프롬프트가 아니라 공교육 공식 문서를 JSON으로 구조화해 화면마다 코드로 인용합니다.

## 1. 기획 의도

교사는 수십 명을 동시에 봅니다. 겉으로 밝은 아이가 관계에서 겪는 어려움을 조기에 알아채기는 어렵고, 종이 설문은 형식적인 답이 나오기 쉽습니다. 사춘기에 들어서는 초등 5학년 담임인 개발자는 "아이들이 가장 편하게 속마음을 여는 AI 챗봇으로 학급의 정서 데이터를 자연스럽게 모으면 어떨까"에서 출발했습니다. '짝꿍이 되고 싶은 친구는 누구야?'처럼 도덕과 동료평가법 중 **추인법**을 챗봇 대화에 녹여 학생의 자신·타인과의 관계를 파악하고, 수집된 데이터가 '보는 것'에서 끝나지 않고 자리 배치·모둠 구성·위기 개입·가정 연계라는 실제 학급 운영으로 직결되도록 만들었습니다.

## 3. 교사의 한 주

**월요일 아침 1분 (대시보드 최상단 '오늘 피드')**
오늘 챙길 학생 한 명(관계 신호 기반, 교사만) · 오늘 아침 활동 카드(교육부 아침조회 주제 + 그 학년의 사회정서 학습 주제, 날짜별 고정) · 오늘 알림장 한 줄(복사해서 e알리미·문자에). 아침 카드는 [TV에 띄우기]로 교실 화면에 바로 보냅니다.

**한 주 동안**
학생들이 챗봇과 이야기하면 소시오그램·감정 신호등·관계 신호가 실시간으로 갱신되고, 학생이 실제로 해 보인 사회정서기술은 성장 기록으로, '이번 주 친절 미션'은 "했어요"로 쌓입니다. 교실 TV의 나무는 미션·연습이 쌓일수록 🌱→🌿→🌳→🌳🍎→숲으로 자랍니다.

**필요할 때**
자리 배치(규칙 엔진 + AI 검토) · 맞춤 처방(학생별 개별화, 성취기준 인용) · 상담·조치 기록 초안 · 가정통신문·학부모 대화 카드 · 학급 리포트 발행(발송 시점은 교사가 결정).

**학기 초·학기 말**
연간 계획서(34주 자동 편성) · 학운위 심의 서식·보호자 동의 안내(.docx, 한글 호환) · 전자 동의 수합 · 운영 결과 보고서(.docx).

## 4. 핵심 기능

### 4-1. 학생 맞춤형 AI 챗봇 (교사 프롬프트 작성 불필요)
- 교사는 [챗봇 설정]에서 말투(다정/차분/유쾌), 이번 시기 관심 주제, 학급 상황 메모, 금지 규칙, 하루 대화 상한(20/30/50/무제한), 수집 범위('긍정 지목만' 모드)만 고릅니다.
- 서버가 매 턴 학생의 오늘 기분·세션 대화 수·누적 일수·이미 지목한 친구·갈등/외로움 이력으로 '이번 턴의 목표'를 정합니다. 체크인 → 오늘 있었던 일 → 긍정 관계 질문(추인) → 마음 열기 → 마무리. 기분이 '힘듦'이면 공감·안정을 우선하고 관계 질문은 뒤로 미룹니다.
- 답변 규칙: 2~4문장, 질문 한 개, 첫 문장은 학생 말에 대한 반응, 설교 금지. 그 학년이 지금 배우는 사회정서 학습 주제를 대화 씨앗으로 써서 "그게 바로 ~하기야"처럼 수업 언어와 연결합니다.
- 퍼지 매칭: "정민이", "ㅈㅁ이"도 문맥 추론 후 학급 명단과 교차 검증해 한 명에게 매핑합니다.
- 태그: `[NOMINATION]` 긍정 지목 · `[CONFLICT]` 갈등 · `[LONELY]` 외로움 · `[ALERT]` 위기 · `[SKILL: 기술명]` 실제로 해 보인 사회정서기술(학년 기술 목록에서만).
- 안전: 사람이 아님을 밝히고 실제 관계로 연결하며 개인정보를 묻지 않는 규칙(서울 AI 가이드라인 학생 핵심 가이드), 정치·유해·성인 주제 거절, 첫 대화 전 'AI 활용 약속' 3가지.

### 4-2. 현장 검증에서 배운 설계 원칙 (이르기·비난·오남용 방지)
실제 적용에서 ① 챗봇이 "걔 나쁘지?"에 공감하며 비난을 강화 ② 한 학생이 매달려 같은 친구 알림 반복 ③ 도구를 이해한 학생이 특정 친구를 반복 신고, 세 문제가 관찰되어 다음을 적용했습니다.
- 비난 동조 금지: 감정 반영 → 사실·해석 분리 → 상대 관점 → 원하는 것의 4단계. 갈등 뒤에는 반드시 강점·긍정 질문.
- 반복 호소 완화: 같은 친구 세션 2회 이상 언급 시 동조·추궁을 멈추고 자기 마음으로 초점 이동, 갈등 태그를 더 쌓지 않음(언급 횟수만 기록).
- 위기 알림 엄격화: 신체 폭력·지속적 집단 괴롭힘·자해·가정 위험·성적 괴롭힘 5개 중대 범주만, 학생당 하루 1건.
- 학생 보고 기준 표시와 교차 검증: 모든 갈등은 '학생이 말한 것'으로 표시하고 상대의 언급 여부·받은 지목 수·관계망을 함께 보여 줍니다. 프로그램은 사실을 판정하지 않습니다. 같은 상대 3회 이상은 '반복 호소'로 구분.
- 조치 기록: 긴급 알림 확인 시 메모와 시각이 남아 '알고 조치했다'는 근거가 됩니다.
- 학생별 자유 대화 모드(`students.freeTalk`): 챗봇이 유일한 출구인 학생을 위해 담임이 [학생 관리]에서 한 명만 지정. 서버는 지목·갈등·외로움·기술 태그를 만들지 않고 추인·관계 질문을 하지 않으며 하루 상한을 적용하지 않습니다. 클라이언트도 위기 알림(5개 범주) 외 저장을 차단합니다. 관계망에는 '자유 대화 모드' 신호가 표시되어 신호 부재가 '수집 안 함'임을 구분합니다.

### 4-3. 학급 관계망·감정·위기 (교사 전용)
- 별자리 테마 소시오그램(상호 지목 화살표, 받은 지목이 많을수록 큰 별), 학급 감정 신호등, 갈등 신호 목록(상호 갈등 우선), 긴급 알림(Red Alert).
- 종합 위험 평가: 위기 알림·상호/일방 갈등·갈등 상대로 언급됨·외로움·관계망 고립(받은 지목 0)을 점수화해 긴급/높음/관심/안정으로 정렬하고, 규칙 기반 '바로 할 수 있는 것'을 즉시 표시.

### 4-4. 자리 배치 (규칙 엔진 + AI 검토)
- 1단계 규칙 엔진(브라우저): 남녀/동성/무관 짝, 갈등 분리, 힘듦 학생 앞줄·분산, 고립·외로움 학생 옆 지지자, 서로 지목한 친구 근접, 직전 짝 반복 회피, 성별 쏠림 방지 — 담금질(Simulated Annealing)로 수천 번 교환. 갈등 인접 금지 같은 절대 조건은 코드로 보장.
- 2단계 AI 검토: 익명화된 배치와 점검표를 Gemini에 보내 설명 근거·보완 사항·첫 주 운영 팁.
- 투명성: 적합도 100점 점수, 원칙별 점검표, 학생별 배치 근거("갈등 상대 ○○와 3칸 분리"). 드래그로 수정하면 점검표 실시간 갱신, 갈등 학생 인접 시 경고.

### 4-5. SEL 맞춤 처방 (학생별 개별화)
- 학생의 관계망·신호·최근 발화를 익명 ID로 치환한 프로필 → 관찰 요약 → 조심스러운 가설 → 강점·관계 자원 → 초점 역량 → 실천 3가지(절차·교사 대사·활용할 또래) → 또래 연결/자리 제안 → 피해야 할 접근 → 1주 후 확인 지표 → 전문기관 연계 기준(JSON).
- 실천마다 서울 성취기준 코드(`standard`)와 도덕과 코드(`moral`)를 붙이고, 서버가 제공 목록에 없는 코드는 걸러냅니다. 다른 학생에게 이미 제안된 전략과 겹치지 않게 하며, 일괄 생성은 순차 실행.
- 처방은 학급 정서 종합 리포트(인쇄)와 상담·조치 기록 초안에 자동 연동.

### 4-6. 성장 기록·친절 미션·가정 회신 루프
- `[SKILL]` 태그 → 학생 문서 `skillLog`(하루 1회) → 학생 화면에서 이번 달 연습한 기술과 배지(🌱1·🌿3·🌳6, 다른 학생과 비교 없음).
- 주간 친절 미션(서울 기술 이름과 연결된 12개 풀, 교사 선택 또는 자동 순환) → 학생 "했어요" → `missions`.
- 교사가 기간(최근 2주/4주/이번 달/학기/전체)과 시점을 정해 학급 리포트를 발행(`classReports`, 개인 정보 없음) → 알림톡·문자 문구 복사 → 학부모는 `/family/:code/report`에서 리포트·이번 주 미션·오늘 저녁 건넬 말을 보고 "집에서 해봤어요" → 익명 회신(`familyFeedback`)이 교사 화면에 건수로.

### 4-7. 가정 연계
- 서울시교육청 「가정연계 가정통신문」 5종(소개·자기·대인관계·공동체·마음건강) + 'AI 활용 가정 지도' 통신문을 학급 정보로 채워 인쇄(`/family/:code/:kind`). 고등은 원문 구조, 초·중은 학년 학습 주제·목표로 자동 구성.
- 학생별 '학부모 대화 카드'는 초점 영역에 맞는 "가정에서는 이렇게" 팁만 담습니다. 기분·지목·갈등·대화는 어떤 가정 문서에도 들어가지 않습니다.
- '이번 주 수업 연계 알림': 차시 하나를 고르면 알림장·문자용 3줄.

### 4-8. 연간 계획·기록·서류함 (학교 제출용)
- [연간 계획]: 학교급·학년으로 34주(2학기×17주) 연간 계획서 자동 편성 — 주차별 서울 차시·성취기준·도덕과 코드·아침 활동·미션·가정 연계 — .docx. 학기 말 운영 결과 보고서(참여·미션·기술·동의·가정 회신 건수) .docx.
- [기록]: 위기 알림·확인 메모·맞춤 처방(근거 성취기준)·연습/미션을 학생별 상담·조치 기록 초안으로 — 복사·.docx. 생활기록부 개인 서술은 만들지 않습니다(AI 작성 금지 지침).
- [서류함]: 도입 절차 4단계(사전 진단 → 의견수렴·필수 기준 → 학운위 심의 → 개인정보 동의) 체크, 서울시교육청 공식 서식 .docx 3종(개인정보 동의 안내 / 서면 심의 안건·결의서·결과 송부 / 우선 사용 서면 보고·보고 양식, 학교명·교장·담임 자동 기입, 한컴오피스에서 HWP 저장), 보호자 전자 동의 링크·전송 문구·제출 현황(동의/미동의/미회신·명단 불일치)·"학생 문서에 반영". 현재 운영 경로는 **학운위 심의 → 동의서 수합 → 운영**입니다.

## 6. 안전·프라이버시

- **관계 데이터는 교사만 봅니다.** 소시오그램·관계 신호·오늘 챙길 학생·상담 기록은 교사 화면에만 있습니다. TV(`/tree`)·학부모(`/family`)·학생 화면에는 이름·지목·갈등·신호가 나가지 않습니다. `classBoards`·`classReports`는 학급 집계만 담습니다.
- 대화 원문 최소 보관(기본): 원문은 저장하지 않고 신호만 기록합니다. 위기 알림이 뜬 대화의 전후 발화만 아동 보호 목적으로 남깁니다. 보호자 동의·학교 절차를 확인한 학급만 원문 보관을 켤 수 있고, 학기 말 일괄 삭제할 수 있습니다.
- 미동의 학생: 보호자가 전자 동의에서 '미동의'하면 챗봇 대화는 하되 관계 신호·성장 기록·미션이 저장되지 않습니다(위기 알림만 유지).
- 익명화 분석: AI에는 실명·닉네임 대신 익명 ID(S1, S2…)만 보내고 교사 화면에서만 복원합니다.
- API 인증: 모든 `/api/*`는 Firebase Auth ID 토큰을 서버에서 검증(`api/_auth.js`). 챗봇은 학급 학생과 교사만, 처방·자리 배치 검토는 교사만. 사용자별 요청 제한.
- Firestore 규칙(`firestore.rules`): 학생은 `studentSessions/{uid}`에 기록된 자기 학급만, 교사는 소유 학급(또는 데모 학급)만. 로그인 없는 요청 전면 차단.
- 국외 이전 고지: 현재 Firebase(Google)·Vercel 미국 리전. 서울 리전·Vertex AI 전환 계획은 `docs/TRUST_PLAN.md`.

## 8. 설치·배포

```bash
npm install
npm run dev        # http://localhost:5173
npm run build
```

환경 변수
- 클라이언트(`.env`): `VITE_FIREBASE_API_KEY` `VITE_FIREBASE_AUTH_DOMAIN` `VITE_FIREBASE_PROJECT_ID` `VITE_FIREBASE_STORAGE_BUCKET` `VITE_FIREBASE_MESSAGING_SENDER_ID` `VITE_FIREBASE_APP_ID`
- Vercel(서버): `GEMINI_API_KEY`(또는 `VERTEX_API_KEY`), `FIREBASE_API_KEY`

Firebase
1. Authentication › 로그인 방법에서 **Google**과 **익명** 사용 설정
2. Firestore › 규칙 탭에 `firestore.rules` 전체를 붙여넣고 게시(firebase CLI가 있으면 `firebase deploy --only firestore:rules`)

## 10. 기대 효과와 다음 단계
