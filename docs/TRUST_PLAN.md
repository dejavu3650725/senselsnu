# 센셀 신뢰 인프라 계획 — "아동 정서·관계 정보 수집" 위험을 제도 안으로

심스페이스가 2,000여 학교에 들어간 방식은 기능이 아니라 **주체·장소·동의·인증** 네 가지를 정리한 것이다. 센셀도 같은 순서로 간다. 아래는 기능 개발이 아니라 서류·설정·절차 목록이며, 대부분은 개발자 혼자 2~3개월 안에 끝낼 수 있다.

## 1. 개인정보 처리 주체를 바꾼다 — 업체가 아니라 학교(교육청)가 처리자

- 지금: 개발자가 사실상 개인정보 처리자. 학생 이름·기분·관계가 개인 계정의 Firebase에 있다.
- 목표: **학교(또는 교육청)가 개인정보 처리자, 센셀은 수탁자**. 학교가 "학생 생활지도 목적"으로 수집하고 센셀은 위탁받아 처리한다. 심스페이스가 서울시교육청과 "정식 계약"이라고 말하는 것이 바로 이것이다.
- 산출물: ① 개인정보 처리 위탁 계약서(표준 양식: 개인정보보호위원회 '개인정보 처리 위탁 표준계약서' 참고) ② 개인정보 처리방침(수탁 항목·목적·보관기간·국외이전 여부·파기) ③ 학교 도입 안내서(교장 결재용 1장: 목적, 수집 항목, 보관, 열람 권한, 위탁 업체, 종료 시 파기).
- 앱 반영: 학급 생성 시 "우리 학교는 위탁 계약/도입 결재를 마쳤습니다" 체크와 계약 문서 업로드란(파일은 저장하지 않고 체크만 기록). 미체크 학급은 데모 모드(가명 학생만).

## 2. 데이터가 있는 장소를 국내로

- Firestore 위치를 **asia-northeast3(서울)**로 생성(기존 프로젝트는 위치 변경 불가 → 새 프로젝트 만들고 이관). Vercel 함수 리전 **icn1**. Gemini는 **Vertex AI(asia-northeast3)** 엔터프라이즈 약관으로 호출 — 입력 데이터 학습 미사용·데이터 위치 지정이 계약에 명시된다. 소비자용 Gemini API 키는 미성년자 데이터·학습 사용 조항 때문에 학교 계약에 부적합하다.
- 산출물: 개인정보 처리방침에 "국외 이전 없음" 또는 "Google Cloud 서울 리전 보관, 미국 등 국외 이전 없음" 명시.
- 앱 반영: `api/*`에서 VERTEX 우선, 리전 고정. 익명화(S1…Sn)는 이미 구현 — 처리방침에 "AI 분석 시 실명 미전송"으로 쓴다.

## 3. 동의를 앱 밖(종이)이 아니라 앱 안에서 관리

- 만 14세 미만은 법정대리인 동의 필수. 지금은 종이 동의서만 있고 앱은 교사의 체크 하나뿐이다.
- 목표: 학생별 동의 상태(동의/거부/미회신)를 교사가 관리하고, **거부·미회신 학생은 챗봇이 데이터 저장 없이 대화만**(신호·지목 저장 안 함, 위기 알림만 유지). 동의 철회·열람·삭제 요청 처리 버튼.
- 산출물: 보호자 전자 동의 화면(학급 코드+학생 이름 확인 → 동의 항목 체크 → 서명). 종이 동의는 교사가 상태만 입력.
- 앱 반영: `students.consent = {status, at, by}` + 규칙: consent≠'granted'면 nominations/conflicts/lonely/skillLog 쓰기 차단(클라이언트+규칙 양쪽).

## 4. 최소 수집을 문서로 증명

- 이미 구현된 것: 대화 원문 기본 미저장, 신호만 저장, 위기 시 전후 발화만 보존, 하루 상한, 학기 말 일괄 삭제, 가정 문서에 개인 신호 미포함.
- 산출물: "수집 항목 표"(항목·목적·근거 성취기준·보관기간·삭제 방법)를 처리방침과 도입 안내서에 동일하게. 성취기준 코드가 여기서 힘을 쓴다 — 왜 이 데이터를 수집하는지 교육과정 문장으로 답한다.

## 5. 인증·실증 — 심스페이스가 간 길

1. **에듀테크 소프트랩 실증**(서울·경기·대구·전남 등 교육청 운영, 무료): 교사 실증단이 한 학기 사용 → 보고서. 신청서에 위 1~4가 있어야 통과가 쉽다.
2. **GS(Good Software) 인증 1등급**(TTA, 비용 수백만 원, 2~3개월): 조달 등록·학교 구매의 사실상 필수 조건. 기능 명세서·시험 대응 필요.
3. **AI 실증 이슈리포트/교육부 추천 목록** 등재: 실증 데이터가 있어야 함.
4. 해외: **COPPA·FERPA 준수 선언 + 1EdTech(구 IMS) TrustEd Apps** 같은 제3자 검토. 국제 진출 시점에.
5. ISMS-P는 지금 규모에 과하다. 대신 "개인정보 보호 자가진단"(개인정보보호위 제공)을 매 학기 수행해 문서로 남긴다.

## 6. 책임 경계를 문서로

- 이용약관에: 센셀은 **보조 도구**이며 진단·판정하지 않는다, 위기 알림은 교사의 확인을 대신하지 않는다, 사안 처리는 학교 절차를 따른다. 화면에도 이미 표시됨(관계 신호 배너·처방 원칙 C·G).
- 알림 누락 책임: "감지되지 않을 수 있다"를 명시하고, 알림 로그(발생·확인·조치)가 이미 있으므로 교사의 조치 기록이 남는다는 점을 도입 안내서에 쓴다.

## 순서와 기간(1인 기준)

1주: 처리방침·수집 항목 표·도입 안내서 초안 → 2주: 새 Firebase 프로젝트(서울) + Vertex 전환 + 이관 → 3~4주: 전자 동의 화면·consent 규칙 → 5~8주: 소프트랩 실증 신청, GS 인증 준비(기능 명세) → 한 학기: 실증 5~10학급 + 사전·사후 측정.

이 여덟 주가 끝나면 "교사가 안심하고 쓴다"는 말을 서류로 증명할 수 있고, 그때부터 사용량은 기능이 아니라 실증 후기와 교육청 채널이 만든다.
